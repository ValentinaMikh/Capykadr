# CapyKadr

Конструктор промтов для семьи капибар (папа, мама, сын) под Nano Banana.
Промт собирается в браузере по готовым шаблонам — без нейросетей.

Сайт: https://valentinamikh.github.io/Capykadr/

## Файлы

| Файл | Что внутри |
|---|---|
| `index.html`, `styles.css`, `app.js` | Интерфейс: вход, конструктор с холстом, «Мои промты», галерея, админка |
| `data.js` | Справочники: персонажи, одежда по сезонам, позы, эмоции, локации, свет, кадр, действия, запреты |
| `builder.js` | Сборка промта и инструкции по справочникам, правила доступности вариантов |
| `config.js` | Адрес проекта Supabase и публичный ключ (права ограничены RLS) |
| `supabase/setup.sql` | Таблицы, правила доступа, проверка пароля команды, хранилища |
| `vendor/` | Библиотека Supabase, внешние CDN не нужны |

## Как устроено

| Что | Где |
|---|---|
| Вход | Supabase Auth: любая почта + пароль команды. Пароль проверяет триггер `private.before_signup`, хеш лежит в `private.settings` |
| Мои промты | `prompt_history`, видит только автор |
| Галерея | `publications` + картинки в закрытом хранилище `works`, отметки — `publication_likes` |
| Аналитика | `events` (копирование промта, эталона, оценки, публикации). Читает только админ |
| Эталоны маскота | Картинки в закрытом хранилище `refs`, список — `ref_images`. Загружает админ в «Админке» |
| Админ | Таблица `admins` (почта). Смена пароля команды — функция `set_team_password` |

## Как добавить вариант

Всё в `data.js`: новая поза — строка в `POSES`, одежда — в `OUTFITS`, локация — в `LOCATIONS`.
Английский текст пишется в поле `en`. Ограничения: `who` (кто может), `outfit` (с какой одеждой).

## Интерфейс по Figma

Конструктор: персонажи → сезон → сюжет → промт. Нижняя панель позволяет
вернуться к любому шагу. «Описать действие» открывает настройки поз, эмоций,
предметов, места, света и формата. Новогодний образ и режим белого фона доступны в версии 2.
Галерея, история и админка сохраняют существующую работу с Supabase.

Оригинальная графика хранится в `assets/figma`, шрифт Roboto Flex — локально.
Временные адреса Figma не используются при работе сайта.

Проверка: `npm ci`, `npm run test:syntax`,
`npx playwright install chromium`, `npm test`.
Браузерные тесты используют тестовый клиент Supabase, не записывают данные
в рабочую базу и сохраняют скриншоты 390/768/1024/1440 px в артефакте
`interface-report` GitHub Actions. Проверка настоящего входа требует аккаунта команды.

Галерея показывает по 15 работ на странице. Сортировка и выбор персонажей
открываются кнопкой фильтров. Фото в галерее и примерах генераций открывают
просмотр с промтом, отметкой «Полезно» и применением настроек. Отметки у
примеров сохраняются в браузере; отметки публикаций — в Supabase.
Управление своими публикациями и модерация доступны через контекстное меню
карточки (правая кнопка мыши или Shift+F10).
На экранах от 1920 px используется компоновка Figma с исходными размерами
изображений и нижней панелью шагов у края экрана.

## Версии конструктора

В админке переключаются общие для команды пресеты: **1 — исходные промты
и изображения**, **2 — текущий стиль (по умолчанию)**. Исходные справочники
и сборщик закреплены в `legacy/` по коммиту
`31069261e3792a573faf4f648cc21c7c97b8c60b`, изменены только имена глобальных
экспортов. Позднейшие загрузки эталонов относятся к версии 2; изображения
версии 1 закреплены в репозитории.

Существующий реестр `ref_images` содержит служебную запись
`id = constructor-version`, `image_path = versions/v1.json` или `versions/v2.json`:
это указатель на комплект конструктора, исключённый из обработки изображений.
Чтение разрешено участникам, запись — только администратору по существующей
RLS. Новая SQL-миграция не требуется. Если записи ещё нет, включается версия 2;
при ошибке чтения сайт не подменяет выбор команды значением по умолчанию.

Версия перечитывается при входе, возвращении на вкладку, каждые 30 секунд
и перед копированием промта. Черновики сохраняются отдельно в браузере.
В историю и публикации записывается `state.constructorVersion`: применить
настройки другой версии можно после переключения команды администратором;
готовый сохранённый промт остаётся доступен для копирования. Версия 1 сохраняет
исходные возможности промтов: без новых режимов белого фона и Нового года.

Обновлённые сезонные фото версии 2 хранятся в `assets/v2/`: 11 оригинальных
PNG, переданных 26 ноября. Они используются в выборе героев, сезонных превью,
админке и скачиваемых эталонах. Весенний образ сына остаётся прежним.
Более ранние загрузки этих эталонов заменены комплектом из репозитория;
последующие загрузки администратора сохраняют приоритет.
